# アプリ構成案：晩ごはん提案アプリ（仮称「きょうのごはん」）

作成日：2026-09-24
前提：`01_research_report.md` の調査結果

---

## 1. コンセプト

> **「30 秒で今日の晩ごはんが決まる。いくらかかるかも分かる。毎日ちがう。」**

| 約束 | 中身 |
|---|---|
| ① すぐ決まる | 開いたら **「今日はこれです」と 1 つだけ指定**。迷わせない |
| ② お金が見える | 1 食の推定費用、1 人前の費用、今月の合計 |
| ③ 作り方がかんたん | 手順は 5 ステップ以内、時間の目安つき |
| ④ 飽きない | 最近のジャンル・食材・味付けを避けて提案 |

---

## 2. 機能一覧と優先度

| 優先度 | 機能 | 内容 | 対応する悩み |
|---|---|---|---|
| **MVP** | 今日はこれです | 主菜 ＋ 副菜（＋汁物）のセットを **1 つだけ指定**。「ほかのにする」で 1 タップ入れ替え | 決められない |
| **MVP** | 冷蔵庫を撮るだけ | 冷蔵庫の写真を AI が読み取り、食材の候補を出す → タップで直して確定 → その食材を使う献立を指定 | 入力が面倒・使い切り |
| **MVP** | 条件の切り替え | 「時短 20 分」「節約」「がっつり」「あっさり」「子ども向け」をタップ | 条件に合わない |
| **MVP** | かんたんレシピ | 材料（人数に合わせて分量が変わる）、5 ステップ以内の手順、調理時間 | 作り方 |
| **MVP** | 費用の推定 | 食材の標準価格 × 使う量 で「この献立 約 ○○円／1 人前 ○○円」 | 食費 |
| **MVP** | 実費の記録 | 「作った」を押すと記録。金額は推定のまま、または 1 タップで修正 | 経費管理 |
| **MVP** | 今月の晩ごはん代 | 月の合計、1 食の平均、予算に対して残りいくら | 食費 |
| **MVP** | マンネリ防止 | 最近の履歴から、同じジャンル・主な食材・味付けが続かないように調整 | 飽きる |
| **MVP** | 買い物リスト | 決めた献立の材料を一覧に。家にあるものはチェックで外す | 買い物 |
| 第 2 段階 | 1 週間の献立 | まとめ買い向け。食材を使い回して無駄を減らす | 食品ロス |
| 第 2 段階 | レシートを撮るだけ | 冷蔵庫と同じ画像読み取りの仕組みで、実際の金額を取り込む | 入力の手間 |
| 第 2 段階 | 家族の好み・アレルギー | 「子どもがピーマン苦手」などを反映 | 家族 |
| 第 3 段階 | 特売・旬の連動 | チラシや季節の食材を優先 | 節約 |
| 第 3 段階 | 家族で共有 | 献立・買い物リストを共有 | 家事の分担 |

## 3. 画面構成

```
[起動]
  └─ 初回だけ：人数／予算（月）／苦手な食材／よく使う条件
        ↓
[ホーム：今日の晩ごはん]  ← 一番よく使う画面
  ├─ 条件チップ：時短｜節約｜がっつり｜あっさり｜子ども向け
  ├─ 「今日はこれです」（大きなカード 1 枚）：料理の写真・名前・約 ○○円・○分
  │     └─ 選んだ理由を一言（例：「昨日はお魚だったので、今日は鶏肉で」）
  ├─ [これにする]（大きいボタン）／[ほかのにする]（小さめ、1 タップで入れ替え）
  ├─ 📷 冷蔵庫を撮る → 食材の候補を確認 → その食材で「今日はこれです」を出し直す
  └─ 今月の晩ごはん代（小さく表示）
        ↓ カードをタップ
[献立の詳細]
  ├─ 主菜・副菜・汁物
  ├─ 材料（人数で分量が変わる）＋ 1 品ごとの推定費用
  ├─ 手順（5 ステップ以内）
  └─ [これにする] → 買い物リストに追加
        ↓
[買い物リスト] ── 家にあるものはチェックで外す
        ↓
[作った！] ── 推定額のまま記録 or 実際の金額を入力
        ↓
[家計（今月）]
  ├─ 月の合計／予算の残り／1 食の平均
  ├─ ジャンルの割合（和・洋・中・エスニック）← マンネリが一目で分かる
  └─ 履歴カレンダー
```

下のタブ：**今日｜買い物｜家計｜履歴｜設定**

## 4. マンネリ防止の仕組み

各レシピに次のタグをつける：

| タグの種類 | 例 |
|---|---|
| ジャンル | 和・洋・中・韓・エスニック |
| 主な食材 | 鶏・豚・牛・魚・卵・豆腐 |
| 調理法 | 焼く・煮る・揚げる・炒める・蒸す |
| 味付け | しょうゆ・みそ・塩・トマト・カレー・甘辛 |

**提案の点数（例）**

```
点数 = 条件との合い具合
     − 最近と同じジャンルなら減点（直近 2 日）
     − 最近と同じ主な食材なら減点（直近 2 日）
     − 最近と同じ味付けなら減点（直近 3 日）
     − 同じ料理なら大きく減点（直近 14 日）
     ＋ 予算の中に収まるなら加点
     ＋ 少しだけランダム（同じ提案ばかりにならないように）
```

→ 点数が高い順に候補を並べ、**一番上を「今日はこれです」として指定**する。「ほかのにする」を押したら、今の案とジャンルが違う次の候補を出す。
→ 完全なランダムにはしない。「ランダムに見えるが、条件と予算と最近の履歴には必ず合っている」ことが大事。
減点する日数は、インタビューの結果で調整する（レポート 4-3 の問い 2）。

## 4-2. 冷蔵庫を撮るだけ（画像読み取り）

**流れ：** 冷蔵庫を開けて 1〜2 枚撮る → AI が「鶏もも・キャベツ・卵・豆腐…」と候補を出す → 違うものを消す・足りないものを足す（10 秒）→ 献立を指定

| 決めごと | 内容 | 理由 |
|---|---|---|
| 在庫を記録し続けない | その日だけ使う。毎回撮る | 在庫管理は続かない（レポート 4-4） |
| 必ず確認させる | AI の結果はそのまま使わず、タップで直す | 容器の中身、引き出しの奥、似た野菜は読み間違える |
| 撮るのは任意 | 撮らなくても「今日はこれです」は出る | 撮ることを必須にすると、使う手間が増える |
| 仕組みを使い回す | 同じ読み取りの仕組みでレシートも読む（第 2 段階） | 開発を 1 回で済ませる |

**注意点：** 画像を AI で読むたびに費用がかかる（1 回数円程度の見込み）。無料版は 1 日の回数に上限をつける、などで調整する。

## 5. 費用の計算

```
1 品の費用 = Σ（食材の標準価格 ÷ 標準の量 × 使う量）
献立の費用 = 主菜 ＋ 副菜 ＋ 汁物
1 人前     = 献立の費用 ÷ 人数
```

- **標準価格 DB：** 食材ごとの平均的な値段（例：鶏もも 100g、玉ねぎ 1 個）。最初は手で作り、定期的に見直す。
- **調味料：** 1 回ごとの金額は小さいので「調味料 一律 ○円」のように概算する（細かくしすぎない）。
- **ユーザーによる修正：** 実際の金額を入れると、その人の「地域・お店の係数」を少しずつ学んで推定が近づく（第 2 段階）。
- **表示の仕方：** 「約 ○○円」と**推定であることをはっきり示す**。

## 6. データ構成（主なもの）

| テーブル | 主な項目 |
|---|---|
| `recipes` | id、名前、区分（主菜/副菜/汁物）、調理時間、手順（配列）、タグ（ジャンル・主な食材・調理法・味付け）、何人分 |
| `ingredients` | id、名前、標準の量、標準価格、単位、カテゴリ |
| `recipe_ingredients` | recipe_id、ingredient_id、使う量 |
| `menus` | id、主菜・副菜・汁物の recipe_id |
| `meal_logs` | id、日付、menu_id、推定額、実際の額、人数 |
| `user_settings` | 人数、月の予算、苦手な食材、アレルギー |
| `shopping_items` | 食材、量、チェック状態 |

## 7. 技術の構成（おすすめ）

| 項目 | おすすめ | 理由 |
|---|---|---|
| 最初の形 | **PWA（ブラウザで動き、ホーム画面に追加できる）** | ストア審査なしで早く出せる。インタビュー相手にすぐ試してもらえる |
| フロント | Next.js（React）＋ TypeScript | 情報が多く、後でアプリ化もしやすい |
| データ | 最初は端末に保存（IndexedDB）→ 後で Supabase などに同期 | ログインなしで始められる＝使い始めのハードルが低い |
| レシピ DB | 確認済みのレシピ 100〜150 品（JSON）から | 正確さと信頼を優先 |
| AI | 第 2 段階：冷蔵庫の中身からの組み合わせや「この案の理由」の説明に使う | レシピそのものは作らせない |
| アプリ化 | ユーザーが定着したら React Native / Capacitor で | 検証が済んでから費用をかける |

**別の案：** 最初から iOS/Android のアプリを作る方法もあるが、検証前に開発と審査の費用がかさむので、おすすめしない。

## 8. 進め方

| 段階 | 期間の目安 | やること | 成功の判断 |
|---|---|---|---|
| 0. 検証 | 2〜3 週間 | インタビュー、画面の試作 | 5 人中 4 人が「30 秒で決まった」と言う |
| 1. MVP | 5〜7 週間 | 上の MVP 機能（冷蔵庫の撮影を含む）、レシピ 100 品 | 2 週間使い続ける人が 40% 以上 |
| 2. 伸ばす | 2〜3 か月 | 週の献立、レシート読み取り、好み | 週 4 回以上使う人が増える |
| 3. 収益化 | その後 | 有料機能（週の献立・家族共有・詳しい家計分析）、または食品・スーパーとの提携 | 有料に移る人 3〜5% |

**見る数字：** 開いてから決めるまでの時間／**1 案目をそのまま採用した率**（目標 50% 以上）／「ほかのにする」を押した回数／週に使った日数／記録された費用の件数
